# ДЗ 5. Оркестрация обработки продаж в Prefect

Поток `hw5-sales-etl` запускается на edge-узле и выполняет три задачи подряд:

1. `check_input` проверяет, что загруженный в ДЗ 4 файл `orders.csv` существует в HDFS и не пуст.
2. `run_spark` запускает Spark через `spark-submit --master yarn --deploy-mode client`. Драйвер работает на edge, а исполнители получают ресурсы через YARN. Spark читает CSV из HDFS, преобразует идентификаторы, даты, количество и цены, отбрасывает некорректные записи и агрегирует данные по дате и региону. Поток сохраняет число заказов, число товаров, выручку и среднюю стоимость заказа в таблицу Hive `hw5.sales_by_region` формата Parquet. Обработанные данные хранятся в HDFS.
3. `verify_hive` читает результат отдельным клиентом Beeline через HiveServer2. В журнале появляются число групп, число заказов и общая выручка.

## Запуск

Нужны работающие HDFS, YARN и Hive из ДЗ 1–3, а также Spark 3.5.9 и входной CSV из ДЗ 4. На Ubuntu установите `python3-venv`, если пакет отсутствует.

На edge-узле из командного репозитория:

```bash
cd HW5
bash run.sh
```

Скрипт создаёт локальное окружение Python и запускает временный сервер Prefect на loopback. Учетная запись Prefect не нужна. Для другой конфигурации задайте `JAVA_HOME`, `SPARK_HOME`, `HADOOP_HOME`, `HIVE_HOME` и `HADOOP_CONF_DIR` в окружении. Адрес ResourceManager и URI Hive Metastore берутся из существующей конфигурации Spark и Hadoop. Для другого входного файла с той же схемой или другого HiveServer2:

```bash
bash run.sh --input hdfs://namenode:9000/path/orders.csv \
  --jdbc jdbc:hive2://hive-server:10000/default
```

Повторный запуск целиком перезаписывает строки только в `hw5.sales_by_region`. Входной CSV и таблицы предыдущих заданий сохраняются. Пустой или некорректный вход приводит к ошибке до записи результата. При проверке Spark считает исходные и валидные строки и сверяет число валидных заказов с суммой `orders` после записи.
